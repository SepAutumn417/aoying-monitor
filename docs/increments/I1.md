# I1 · 登录、设备与实时推送

状态：**待验收**
日期：2026-11-05
版本：后端 0.2.0 · Web 0.2.0 · Android 0.2.0

## 本增量解决什么

I0 只有静态界面。I1 把「谁在用这套系统」和「服务器怎么把消息推到手机」打通：登录拿到令牌 → 注册设备 → 拿到一次性 WebSocket 票据 → 建立长连接 → 服务器产生的事件实时到达 → 断线后能补发漏掉的事件。数据采集还没有接（那是 I2 之后），所以现在页面里展示的仍是示例数据，但实时链路是真的。

## 做了什么

| 端 | 内容 |
| --- | --- |
| 后端 | 用户/设备/会话/WS 票据/事件 5 张表；bcrypt 密码；30 分钟访问令牌 + 30 天刷新令牌轮换；一次性 WS 票据；进程内事件广播 + 事件表补发；`/healthz` 真实检查数据库 |
| Web | 登录页真实表单；路由守卫（未登录跳登录并记住原目标）；自动恢复会话；全局单条 WebSocket；设置页设备列表（断开设备）+ 发送测试推送；侧栏与顶栏显示实时连接状态 |
| Android | 登录/会话恢复；同一套令牌逻辑（刷新令牌存 Secure Storage 之外的 SharedPreferences）；全局 WebSocket；顶部连接状态；设置页设备管理 + 测试推送 |
| 部署 | `docker-compose.yml` 增加 `api` 健康检查与认证环境变量；`.env.example` 补全 `ADMIN_*`、`JWT_SECRET`、`WS_TICKET_TTL_SECONDS`、`REFRESH_TOKEN_TTL_DAYS` |

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/login` | 用户名密码 → 访问令牌 + 刷新令牌 + 设备 |
| POST | `/api/auth/refresh` | 旧刷新令牌立即失效并换发新的（轮换） |
| POST | `/api/auth/logout` | 撤销当前刷新令牌 |
| GET | `/api/auth/me` | 当前用户与设备 |
| POST | `/api/ws/ticket` | 签发 60 秒、只能用一次的 WebSocket 票据 |
| GET | `/ws?ticket=` | 长连接：`hello` → `event` / `replay` / `pong` |
| GET | `/api/devices` | 设备列表 |
| DELETE | `/api/devices/{id}` | 软吊销设备并广播 `device.revoked` |
| GET | `/api/events?after=&limit=` | 事件回放（最多 200 条） |
| POST | `/api/events/test` | 发一条 `system.test` 事件，用于验证推送链路 |
| GET | `/healthz` | 数据库连通性 + 最新事件 id |

## 已知限制

1. **数据仍是示例**：持仓、发言、提醒来自 `web/src/lib/demo.ts` 与 `app/lib/data/demo.dart`，顶部有「示例数据」徽标。真实来源在 I2–I6 接入。
2. **单进程广播**：事件广播在进程内完成，`api` 只跑 1 个 worker。多 worker 需要换成 Postgres `LISTEN/NOTIFY`，接口不变。
3. **没有 APK**：本机无 Java/Android SDK，只能说 Flutter 代码与测试通过，装到手机上要等部署阶段。
4. **Android 推送还没接管系统通知**：现在是应用在前台时刷新界面；后台唤起通知属于下一步（前台服务 + 本地通知）。
5. **管理员密码**：`ADMIN_PASSWORD` 留空时首次启动随机生成并打印到日志，请在那时记录下来。
6. **只读**：系统不发起任何交易，只有读取与提醒。
