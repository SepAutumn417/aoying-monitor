# I4e · 历史信号解析与真实账本落地

状态：**本地导入与页面验证完成，待用户验收**。

本轮在用户同意继续推进后，将已有 Telegram 归档解析进 I4d 使用的本地账本。不更改解析器、交易规则或数据库结构，不下单、不创建影子委托、不打开 Telegram 自动采集，也不操作手机前台。

## 先备份、先试跑，再导入

1. 使用 SQLite backup API 备份仓库根数据库，并生成独立试跑副本。导入前确认 `signals`、`positions`、`position_events`、`copy_positions`、`copy_intents` 均为空，避免覆盖已存在的交易账本。
2. 仅在副本执行现有 `rebuild_from_messages`，检查仓位最终已实现值与最后一个动作一致，已平仓数量为零。
3. 通过已认证的本地 `POST /api/signals/rebuild` 执行正式导入，再用只读 API 核对与试跑结果一致。
4. 比对原始消息 SHA-256、检查 SQLite 完整性和外键，以及没有补发历史 `signal.*` 通知、没有产生跟单委托。

[导入前备份](<../../.tools/backups/history-ledger-20261109T071115Z/before.sqlite>) 与试跑数据库仅保留本机，不提交 Git。原始归档指纹为 `9067063a1797ead55ce09bf49b081ba6f2b0396e2511910c3b0e865786de77c3`，导入后不变。需要恢复时应先停止服务、另行确认恢复操作；本轮未执行回滚。
