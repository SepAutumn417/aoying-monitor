状态：**实现与自动化验证完成，待用户验收**。本增量未重新构建或安装 Android APK，未进行手机前台/声音验收。

## 目标

保持 0.4.0 的导航和设计语言，把 Web、Flutter 的总览与仓位页面从演示数组切换到现有 Telegram 信号账本 API。跟单执行不在本增量中。

## 数据口径

- `GET /api/copy/status`：全局未平仓、已平仓、已平仓累计已实现、最后信号时间。
- `GET /api/positions`：仓位与事件生命周期；页面只展示有限条数，不能把一页合计当成全局统计。
- `GET /api/signals`：最近信号。
- 账本记录描述被监控交易员的报送，不是我方 Bitget 账户，不是行情接口，也不是当前交易所对账结果。
- `realized` 在仓位和事件层都是累计已实现，不能把历史事件值相加。缺失值与真实零值分别显示。
- 新信号只触发重新读取 API，不靠推送 payload 猜当前仓位。

## 使用开发工具的边界

设计工作台已打开真实开发服务器，不以静态稿代替实际业务页。工作台无头检查落在未登录页面，不能当作业务页验收结果。Midscene 桥配置接口本轮超时，没有完成 Midscene 端到端测试；改用 Playwright + Edge 完成真实后端、真实登录的业务页断言，不将两者混称。

只读测试请求未重建账本、未发测试交易信号、未调用交易所接口。组件测试中的有仓位数据仅为自动化夹具，不注入当前服务器。三个 GET 在客户端同时读取并统一提交视图，后端并未提供事务快照令牌，不能声称三次读取是同一个数据库瞬间。

本轮审查另外修正了 Web 将浮盈称作“累计浮盈”的文案，并先写失败回归测试再修复：只有已实现采用仓位累计口径，浮盈是报送时的快照。
