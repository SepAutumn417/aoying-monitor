## 实现

- 新增 `telegram_topics` 与消息 `topic_id`；已有数据库做幂等、加字段式升级，不删除账号/消息/会话文件。
- 每区独立回补最近 200 条及维护游标；General 按 forum 标志筛选群历史，不把普通回复线程误认为分区。
- 每轮最多扫描每区 20 页、每页 200 条；稀疏 General 首次回补保留进度，下轮继续。区间失败保留原游标，记录错误，其它区继续。
- 增量补洞之外，重读最近窗口以修复离线编辑；额外重读已知最新、可信机器人的“当前全部持仓”快照。编辑清空文本/移除媒体也保留旧版。
- 回补原文静默入库，不伪装为新交易事件；实时消息/编辑仍走既有 WebSocket。启动回补与手动/定时补拉共享互斥锁。
- 时间线支持分区、重点动态/本人发言/全部原文及原有类型/日期筛选。跨区回补按消息时间排序，分页沿同一排序继续。
- 数据源页显示四区消息数、同步时间与错误。禁止关注非目标群，“发现会话”只查询目标群。

## 限制与后续

- 离线编辑修复有窗口边界，不声称覆盖全部古老历史；快照固定重读只针对已入库且可识别的最新报告。
- 文本修订与媒体类型留档，不保存每一历史媒体文件；本阶段没有图片展示/下载接口。
- 用户可选的全文搜索仍只搜索当前加载的最多 100 条，不是全库检索；页面需要刷新以获取静默补拉后的状态。
- 真实网络恢复、所有类型删除事件和长时间稳定性尚未做完整故障演练；删除缺少 chat_id 时保守忽略，避免误删其它群消息。
- 后端测试仍出现原有 Starlette 弃用、SQLAlchemy 连接清理及 aiosqlite loop-closed 警告；测试退出码为 0，不等于警告已修复。
- Docker 和 Android 真机本轮未验收。仅本机 API 单 worker；相对 SQLite URL 必须从仓库根目录启动，Telegram 会话/媒体路径则锚定仓库根目录。
- 下一步先做最小 I2.2 迁移基础，再做可信机器人动作/快照的确定性解析；AI 文本/图片与手机通知后置，须另行验收。
