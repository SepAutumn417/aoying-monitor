## 二、一件必须先承认的事实：跟单必然滞后

链路：

```
熬鹰在交易所下单
   ↓  （他那边：交易所回报 → 机器人整理 → 发到 TG，这一段我们看不见）
Telegram 推到我们         ← 通常在 1 秒内
   ↓  解析（确定性 parser，毫秒级）
决策
   ↓  OKX/币安 REST 下单    ← 100~300ms
成交
```

**总延迟的绝大部分消耗在「他发消息之前」那一段**，我们无法观测也无法压缩。
实测量级：**3～20 秒**（他手动发消息时更慢，机器人自动推时更快）。

由此直接得出两条硬性原则：

1. **这是「跟随」，不是「抢跑」。** 入场价差（滑点成本）是固定支出，必须计入收益模型，不能假装不存在。
2. **不要把入场价当成他的开仓均价来记账。** 必须记我方真实成交价，否则复盘全是幻觉。

## 四、AI 用在哪、绝不用在哪

### 不该用 AI：仓位信号

「熬鹰交易信号 / 📈 注意，加仓 / 币种：BTCUSDT 永续 | 全仓 | 5x / 原仓位：584.57 ZEC / 现仓位：597.44 ZEC /
开仓均价：1563.54 USDT / …」这是**固定模板**，格式稳定。

用确定性 parser 的理由：
- 毫秒级、零 token 成本、可单测、可复现
- 出错时知道错在哪个字段，能生成告警
- 大模型在关键路径上引入不可解释的不确定性，这是不能接受的

### 该用 AI：群聊里的观点

「可能会玩到 20 号」「MEXC 有钱的速度提现」「到时候用这 14wu 1x杠杆做，只给方向」
——这些没有模板，抽的是**意图、币种、方向、态度、时效、可信度**。

### AI 的角色：只否决，不发起

```
parser 发现「熬鹰开仓 BTC」
   ↓
问 AI：最近的聊天里，有没有与这次跟单相矛盾的信号？
   ↓
有 → 拦下，推给我人工判断
没有 → 按规则跟
```

**让 AI 当过滤器而不是触发器**，它的错误方向是「少赚」而不是「多亏」，安全一个数量级。

## 五、风控红线（我认为不可协商）

### 1. 密钥权限最小化

- 只开**交易**权限，**永久禁用提现权限**
- 绑 IP 白名单（服务器固定 IP）
- 密钥只放服务器 `.env`，不入库、不进前端、不进 git

这条能从原方案「不存提现密钥」平滑过渡，不算推翻。

### 2. 用机器人快照做最终对账

熬鹰的机器人**每次动作后会推一份全量持仓快照**（「熬鹰当前全部持仓」）。
信号消息可能被编辑或删除（数据库里已有 36 条编辑历史），如果只信信号，可能跟到一个他已撤销的仓。

**以快照为准核对，信号只负责触发。** 这是本系统相对市面跟单工具的结构优势，必须用上。

### 3. 强平价必须比他更远

这是最容易出人命的一条：

- 熬鹰用**全仓 + 巨额保证金**（单笔最大保证金 850,442 USDT），他的强平价离现价很远
- 如果我们用「小保证金 + 高杠杆」照抄方向，**我的强平价会离现价很近**
- 结果：一次他轻松扛过去的回撤，会先把我们打爆

因此：**跟单仓位的强平价必须计算出来并确认比他的更远**，做不到就不跟，不能"先跟上再说"。

### 4. 杠杆与规模必须有硬上限

熬鹰杠杆 5x–20x，单笔保证金最高 85 万 USDT。照抄规模会瞬间爆仓。
必须：`跟单规模 = 我的总资金 × 单笔比例上限`，且 `杠杆 ≤ min(他的杠杆, 我的上限)`。

### 5. 减仓/平仓必须跟

只跟开仓不跟平仓 = 敞口无限累积，比不跟更危险。

### 6. 独立 kill switch

一个不依赖策略代码、不依赖数据库的手动停止开关（文件信号 / 独立进程检查），出问题时能秒停。

## 六、推进顺序（影子跟单先行）

### 为什么先做影子

跑通全链路但**不下单**，只记录：
- 如果跟了，会在什么价位成交（真实盘口模拟）
- 滑点多少、延迟多少
- 这一单到现在浮盈浮亏多少
- 我方模拟持仓 vs 熬鹰真实持仓的差异

跑一到两周，就有真实数据回答「跟单到底值不值」，而不用先亏钱去买这个答案。

### 增量路线

| 增量 | 内容 | 验收标准 |
| --- | --- | --- |
| **I3a 信号解析入库** | 确定性 parser + `signals` / `positions` / `position_events` 三张表；幂等、可重放 | 用库里 200 条真实消息重放，解析出 17 个仓位、96 次动作，与人工核对一致 |
| **I3b 影子跟单** | 决策规则 + 模拟成交 + 滑点/延迟统计 + 我方 vs 熬鹰对账 | 连续运行不产生任何真实委托；对账差异有解释 |
| **I3c AI 语义层** | 观点抽取 + 作为否决器接入；每条结论回链原文 | 抽取结果可人工复核；否决有理由 |
| **I4 实盘执行** | 单交易所下单适配器 + 风控硬上限 + kill switch + 对账自愈 | 小资金跑通一笔完整的开→加→减→平 |
| **I5 手机确认** | Android 通知 + 一键确认（半自动模式） | 手机上能看到信号并确认 |
| **I6 全自动** | 去掉人工确认，只保留否决与熔断 | 连续 N 天无不合理委托 |
| **I7 多来源** | X / OKX 只读 / fomo 链上 | 各自可独立验收 |
| **I8 稳定性** | 72 小时 soak、备份恢复、APK 分发 | — |

**建议模式演进：影子 → 半自动（推送 + 点确认）→ 全自动。**
全自动也可以直接做，但那意味着第一笔真实跟单就是第一次实盘测试。

## 七、需要你定的事（2026-11-07 已定，见 §九）

1. **跟多少？**
   - A：按熬鹰仓位固定百分比（如 2%）
   - B：固定预算，每单固定 USDT
   - C：按我账户权益的固定比例
   这直接决定风控代码怎么写。

2. **在哪家交易所下单？** OKX 还是币安。两家下单 API 差异不小，先做一家。

3. **过渡模式？** 影子 → 半自动 → 全自动（我推荐），还是直接全自动。

4. **容错底线？** 单笔最大亏损、日内最大亏损、连续亏损多少单停下。这三个数必须由你定，我不能替你定。

## 九、定稿口径（2026-11-07）

### 唯一的换算规则：对齐「实际杠杆」

**不估算他的本金，也不用他的本金。** 机器人每条信号里已经直接给出了 `实际杠杆`，
而 `实际杠杆 = 仓位名义价值 ÷ 账户权益`——这正是「他多少爆仓，我们就多少爆仓」的那个量。

```
我方名义价值 = 信号里的「实际杠杆」 × 我方合约账户权益
我方数量     = 我方名义价值 ÷ 下单前标记价 ，向下取整到 sizeMultiplier
杠杆档位     = 照抄信号里的「杠杆」（只影响保证金占用，不影响爆仓距离）
保证金模式   = 全仓 crossed
```

由此得到的性质：

- 我方 `名义 ÷ 权益` 恒等于他的 `名义 ÷ 权益` → **爆仓的价格百分比距离一致**；
- 资金小不会被迫放大杠杆，也不会因为资金大而变得更安全——比例是同一个；
- 他权益变了（落袋、加保证金）会体现在下一条信号的 `实际杠杆` 里，我们自动跟上。

### 目标式而不是增量式

每个动作都算「该持有多大」，再和「现在持有多大」求差：

| 信号 | 目标名义 |
| --- | --- |
| 新开仓 / 加仓 / 减仓 / 调杠杆 | `实际杠杆 × 我方权益` |
| 平仓 | 0 |

`下单量 = (目标名义 ÷ 标记价) − 当前持仓量`。这样即使中间丢了一条信号、
或者某一单被交易所拒掉，下一单也会自动把仓位拉回正确比例，不会累积漂移。

### 权益从哪来

**不配置、不估算**：每次动作前调 Bitget `GET /api/v2/mix/account/account` 读
`USDT-FUTURES` 的 `accountEquity`（含未实现盈亏），用这个数做基数。
凭证由用户在 I4 前提供（只勾合约交易、关闭提现、绑 IP）。

影子跟单阶段没有凭证，用一个 `COPY_EQUITY_USDT` 配置值代替，数字变了不影响逻辑。

### 风控

- **不设容错底线**：等比照跟，不加单、不补仓、不砍仓。
- 唯一额外规则：**每单平仓后，把该单利润的 50% 从合约账户划到现货账户，只出不进**。
  亏损不平摊、不追补。
- 交易所拒单 → 记 `failed` 并推送，**不重试**；下一笔信号会重新对齐目标。
