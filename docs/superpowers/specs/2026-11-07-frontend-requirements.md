## 一、核心初衷（排序即优先级）

1. **熬鹰一开仓，我要第一时间看到。** 这是整个系统的第一目标，其他都可以让步。
2. 看到之后，我要能跟着这个仓位走：开仓时什么样，中间加仓/减仓/调杠杆，最后怎么平的。
3. 事后我要能回头查：那天他到底说了什么、什么时候改过。
4. 提醒只服务第 1 条，不要变成第二个消息列表。

## 二、数据真相（必须先讲清，避免再出现误解）

| 数据 | 真实来源 | 现状 |
| --- | --- | --- |
| 交易信号（开/加/减/平/调杠杆） | Telegram「熬鹰交易信号推送」机器人 | 已采集原文，**尚未解析成结构** |
| 全部持仓快照 | 同群「熬鹰带单仓位信息推送」机器人 | 已采集原文，**尚未解析** |
| 本人观点、禁言群通知 | 「聊天群」「禁言群」「消息通知」 | 已采集原文 |
| OKX 实盘 / fomo / X | 未接入 | 无 |

已核对的真实动作分布（200 条交易区消息）：新开仓 17、加仓 42、减仓 13、平仓 18、调杠杆 10；币种 BTC/ETH/CL/CRCL/HYPE/MU/SNDK/ZEC。

**结论：系统里不存在"我的账户"。所有数字都是熬鹰的。** 因此前端不再需要任何"这是谁的"标注，也不显示没有任何来源的汇总指标。

## 三、页面级需求

### R1 总览（首屏）

- 首屏第一眼必须是**当前持仓 + 最近一次动作**，不允许出现"名义总仓位/未实现盈亏/今日已实现"这类无来源的假汇总。
- 最近一次**开仓**必须置顶，且比其他内容更醒目（更大字号、更强对比）。
- 界面中不允许出现示例数据；没数据就说明为什么没数据。

### R2 仓位动态流

- 每个仓位是一条可跟随的记录：开仓 → 加仓/减仓/调杠杆 → 平仓，按时间正序展开。
- 每个动作要带：动作类型、方向、价格、数量、杠杆、当时的已实现盈亏。
- 仓位结束后保留在列表里，可折叠，不消失。

### R3 持仓

- 一个仓位一张卡，卡内就是它自己的时间线，不再用横向多列表格。
- 卡片头部只放最有用的四件事：币种、方向、当前/平仓状态、浮动盈亏。
- 已平仓位与持仓中仓位分开，默认只看持仓中。

### R4 实时性

- 机器人推送后，页面必须在数秒内出现新动作，无需手动刷新。
- 断线重连后自动补齐断线期间的动作。

### R5 发言（原文）

- 现有能力保留：分区筛选、重点/本人/全部、类型筛选、时间范围、编辑历史。
- 原文是仓位数据的证据来源，从仓位卡应能一跳看到对应的原始消息。

### R6 提醒

- 只承担一件事：开仓/平仓这类关键动作的提醒。
- 不再展示与仓位无关的提醒。

### R7 数据源

- 展示每个分区最近同步时间与条数，异常要显式报错。
- 未接入的平台显示"未接入"，不显示假状态。

### R8 设置

- 保持现状即可（账号、设备、退出）。

## 四、明确不做（本轮）

- 不做跨场所净额、不做收益率归因、不做任何下单/转账。
- 不在本轮接入 OKX / fomo / X（下一轮做）。
- 不做移动端重排（Android 在更后面的增量）。

## 五、已知缺口（决定工作顺序）

1. 后端还没有 `signals` / `positions` / `position_events` 三张表，前端现在的持仓页是无源之水。
2. 因此顺序是：**先解析入库 → 再做前端**，否则前端只能画假数据。
