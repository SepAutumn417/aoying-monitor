# P1：通知链路验证与部署关卡

状态：配置草案，尚未部署，不代表已验收。

## 决策

用户没有域名。先评估可信 IP 证书及自动续期，不默认 HTTP 或跳过 TLS 校验。
采用独立 systemd Gotify 二进制服务，127.0.0.1:18081，仅通过受保护 HTTPS 入口公开。
不修改旧 Telegram 服务、数据库、session，不把未提交的旧项目改动复制上线。
首次测试只发送合成数据；先验证消息传输，再验证声音，最后才接真实监控。

## 部署前清单

- 固定 Gotify 发布版本，校验官方发布文件；确认版本支持配置项。
- 确认独立端口空闲、服务账号无登录权限、状态目录与配置权限。
- 明确 HTTPS 独立端口/入口与防火墙变更，不覆盖旧 nginx 配置。
- 确认证书签发、续期、失败告警和客户端信任；证书服务条款如需接受由用户处理。
- 创建独立管理员、接收账号、应用令牌；令牌不得写入 Git 或测试记录。
- 本机探活、认证失败验证、发送消息、WebSocket 收消息及服务重启恢复通过。
- 保存旧服务健康基线，变更后核对旧服务状态。

## 手机验收

先记录 K50 系统版本、Gotify 客户端版本、通知/声音/省电设置。
每条测试含 run_id、sequence、UTC 发送时间；Gotify 接受仅算服务端结果。
手机实际到达时间另行记录，不能用 HTTP 200 代替。

| 场景 | 需观察 |
|---|---|
| Wi-Fi，VPN 关闭，亮屏 | 到达数量、延迟、声音 |
| 移动网络，VPN 关闭，锁屏 | 到达数量、延迟、声音 |
| 锁屏待机至少两小时 | 是否延迟或断连 |
| 清理最近任务 | 是否保持连接；与系统强行停止区别记录 |
| 网络关闭再恢复 | 补收数量、顺序、断连显示 |
| Wi-Fi/移动网络切换 | 重连时间、漏收、重复 |
| 正常服务重启 | 客户端恢复、消息保留 |
| 连续仓位变化模拟 | 每条提醒、合并行为、响铃强度 |

建议总计至少24小时、100条序号测试。正常在线场景目标100%到达、P95≤5秒；离线场景独立统计。
结果写入 work/，只提交脱敏汇总。未通过时定位原因再复测；禁止据一次成功承诺必达。

## 回滚

停止并禁用新服务；撤销仅属于新服务的入口与防火墙规则；保留数据供排查。
不停止旧服务、不删除旧库、不执行全目录覆盖或旧仓库 pull。
