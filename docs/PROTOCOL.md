# P1 协议 v1 与实现决策

本阶段只传合成测试事件，业务采集、交易执行和AI不在范围内。

## 技术选择

服务端Python/FastAPI、SQLite事务事件日志；安卓原生Kotlin，Room持久化，OkHttp WSS。具体库版本在构建前核实固定，不采用未经验证的动态版本。
SQLite日志是断线补收的持久化来源；内存广播仅用于唤醒连接，不作为唯一投递依据。

## 设备认证

管理员通过服务器本地命令创建设备，返回一次性展示的随机设备Bearer令牌；数据库只保存令牌摘要。
手机扫码或手动录入可信HTTPS地址与设备令牌，密钥存储方案在安卓阶段验证。不得把令牌放URL、普通日志或Git。
设备凭证仅能读取分配给自己的事件和提交自身回执，不能创建事件或访问管理功能。撤销需关闭已有连接，不能仅拒绝下次登录。
P1管理员创建测试事件只走服务器本地命令，不暴露公共测试发送接口。

## 事件

每设备一个递增sequence；event_id使用随机UUID。重复来源键只生成一次事件。
字段：protocol_version=1、sequence、event_id、kind、title、body、source_time、created_at、expires_at、synthetic=true、source_reference。
P1 kind仅test。后续position_change/opinion/dynamic/snapshot由采集阶段引入。
源时间和创建时间UTC ISO8601；正文限制16KiB；连接与重放批次均限制大小。

## 连接与补收

WSS /v1/stream，用Authorization请求头认证。手机首帧发送hello(version=1,after=本地连续落库游标)。
服务器先发ready，再按sequence升序重放。接收循环与发送循环独立，避免持续发消息时不能处理回执。
每30秒心跳，90秒无响应断开。手机指数退避并加随机抖动，最高30秒；网络恢复主动重连。
after只表示本地已连续落库，不表示用户看过。游标超出服务器范围拒绝并提示同步错误，不静默跳过。
GET /v1/events?after=N&limit=100使用同一设备认证，提供分页恢复接口；保留期造成缺口时明确返回gap，不声称补收完整。
P1暂不自动删除事件；上线真实消息前确定保留期与容量上限。

## 回执与提醒

手机在Room事务中去重、保存事件并推进连续游标，再发received(sequence,event_id)。
用户点击已知晓发送acknowledged(sequence,event_id)；重试回执幂等，不能确认不属于设备的事件。
手机已保存但服务器未收回执时允许重放；重复事件不重复响铃。
声音停止与已知晓语义分开：停止只是停止本次声音，不自动表示已交易。
临时默认建议：测试响铃最长60秒，必须有停止按钮；多条事件逐条保存，新事件进入同一提醒会话并展示未确认数，避免多音轨叠加。此默认在设备实测前向用户展示并可调整。
超过expires_at的事件补收时显示过期且不响铃；P1测试事件有效期5分钟。不同事件kind不等于交易价值分级。
不保证原子实现“响铃恰好一次”：崩溃可能发生在保存与播放之间，需记录提醒状态并在恢复时展示待处理事件，不能隐瞒这一边界。

## 安全与验收

正常校验TLS；服务端运行账号无root权限；数据库/备份权限受限；跨设备隔离、撤销、重放、并发重复、异常游标必须测试。
服务器接受、WSS写出、手机落库、用户已知晓分别记录；只有手机回执可表述为设备收到。
