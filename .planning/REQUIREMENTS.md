# Requirements: 熬鹰资本监控（Web优先）

**Defined:** 2026-10-30，用户明确调整顺序。
**Core Value:** 稳定采集真实观点与仓位变化，并在Web清楚、及时、可追溯地展示。

## v1 Requirements

- [ ] **AUTH-01**: Web需登录访问，安全会话、退出及权限隔离经验证。
- [ ] **DATA-01**: 原文、编辑版本和标准事件持久化，去重且重启后可恢复。
- [ ] **WEB-01**: Web提供可用的登录、时间线/详情及监控状态页面；无数据和失败明确区分。
- [ ] **OPS-01**: HTTPS、非root服务、密钥不入库和日志脱敏在接入真实内容前落实。
- [ ] **TG-01**: 四话题按稳定ID采集，本人/助理身份清楚，原文可追溯。
- [ ] **TG-02**: 同条消息编辑和周期核对识别开加减平，价格/浮盈刷新不误报。
- [ ] **TG-03**: 采集断线和重启后补收，缺口与失败可见，不把不完整快照当平仓。
- [ ] **WEB-02**: 在Web查看真实Telegram发言、当前仓位、变化记录和前后依据。
- [ ] **X-01**: 核实本人账号和合法可用入口后采集推文，原文链接/时效/限频/回填可核对。
- [ ] **FOMO-01**: 核实Fomo平台/账号/地址和权限后监控可获取交易仓位，未知字段不伪造。
- [ ] **OKX-01**: 核实OKX公开入口和权限后监控可获取交易仓位，不假设可读私人订单。
- [ ] **WEB-03**: Web统一跨平台动态/仓位/操作历史和来源筛选，证据充分才合并重复信息。
- [ ] **OPS-02**: 容量/保留期、备份恢复、来源断线与独立整机探活有验收证据。
- [ ] **PRIV-01**: 复核Web会话、访问控制、存储/备份/密钥边界，不虚称端到端加密。
- [ ] **E2E-01**: 对已接入真实来源做长时运行与Web端到端验收，报告实际延迟/缺口/恢复；平台受限须用户确认范围变更。

## v2 Requirements — 安卓App（v1验收后再规划）
- **APP-01**: K50 Android14自有客户端后台接收，显示连接与权限状态。
- **AUTH-02**: 设备独立凭证与撤销，已有连接失效。
- **ACK-01**: 设备落库与用户已知晓分别回执，停止声音不等于已交易。
- **ALERT-01**: 每次有效仓位变化声音/振动、持续响铃及手动停止，经真机验证。
- **APP-02**: 连续游标补收、正常重放不重复提醒、过期标记、崩溃边界可见。
- **APP-03**: K50至少24小时100条分场景接收与声音测试，不承诺强停/关机必达。

## Later Requirements — AI
- **AI-01**: 原文/仓位上下文生成交易对关注清单，事实与推断区分，引用可追溯。
- **AI-02**: 先明确模型数据披露和人工评估，失败不阻塞监控。

## Out of Scope
自动交易、Gotify、第三方通知SaaS、未经核实的私有订单可见性。v1不包含手机后台叫醒保证，网页声音仅用户授权且页面/浏览器允许时提供，不能代替后续App。
