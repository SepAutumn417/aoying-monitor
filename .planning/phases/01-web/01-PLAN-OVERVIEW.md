# 第一阶段详细方案：服务端与 Web 可用基础

日期：2026-10-30。状态：**方案待用户确认，未开始开发、安装或部署**。

## 这一阶段交付什么

你能用浏览器安全登录自己的系统，在一个地方查看已保存的信息、打开原文和编辑版本，看到各来源是否已接入及系统是否可用。

本阶段用明确标注“测试数据”的合成记录走通流程，真正的 Telegram 监控在第二阶段接入。X、Fomo、OKX、手机 App、AI 和自动交易不进入第一阶段；来源未接入会如实显示，不用测试数据冒充业务成果。

## 四个页面

| 页面 | 你能做什么 | 第一阶段验收重点 |
|---|---|---|
| 登录 | 单账号登录、显示或隐藏密码、退出后无法继续读取记录 | 无注册和营销；登录错误/尝试过多/网络故障区分；不泄露账号是否存在 |
| 信息时间线 | 看来源、作者、类型、原始时间、采集时间及摘要；筛选、刷新、加载更早记录 | 每条测试标记；读旧信息时更新不抢位置；空列表和错误不同 |
| 信息详情 | 阅读完整原文、查看来源与已保存的编辑版本 | 原文纯文本；一个或多个版本如实显示；不提前宣称已识别真实仓位操作 |
| 监控状态 | 看 Telegram、X、Fomo、OKX 的接入状态与系统查询状态 | 四平台当前“未接入”；系统能查询不等于平台在线；错误与旧数据明确标记 |

推荐外观是中文、中性浅色、单列信息卡片，正文为主要阅读焦点。桌面侧导航，手机浏览器窄屏导航换行，长中文和链接不撑破页面；兼容键盘和触摸。详细尺寸、配色及文案见 [界面规范](01-UI-SPEC.md)，都属于本次待确认的推荐设计，不是此前已指定的偏好。

## 服务端与数据设计

推荐 Python/FastAPI 提供 API、SQLite 保存数据，React/TypeScript/Vite 构建 Web；不引用外部字体、统计或运行时 CDN。浏览器与 API 同一站点，由现有 nginx 提供正常验证的 HTTPS。

```text
本地管理命令写入测试信息
        ↓
来源 → 原始消息 → 不可变编辑版本 → 标准事件
        ↓ 同一数据库事务
已登录用户的查询 API
        ↓
时间线 → 详情/原文版本 → 来源与系统状态
```

| 表/职责 | 保存内容与约束 |
|---|---|
| sources | 平台、来源身份、显示名、接入状态；当前真实来源未接入 |
| raw_messages | 来源＋外部消息ID唯一，表示“同一条原始消息” |
| raw_revisions | 该消息每个稳定版本；正文A→B→A仍保存3个版本，不仅按正文去重 |
| events | 标准事件ID、递增序号、关联原文版本、类型、时间、测试标记；重复事件键只保存一次 |
| users / sessions | 单账号密码摘要、随机会话摘要、失效/撤销与CSRF；不存明文密码或原始会话令牌 |
| schema_migrations / login_attempts | 明确数据库版本和持久化登录限频记录 |

原文、版本与相关事件在一个事务中提交，出错全部回滚。新生产库与已有按设备的原型日志分开，不自动覆盖或导入旧文件。保留两项原型回归，再加原子写入、并发去重、版本恢复、备份恢复测试。第一次数据模型为新库提案；未来若变更已发布格式或需要覆盖数据，必须先明确迁移/恢复方案，不静默清库。

### API 范围

| 接口 | 用途 |
|---|---|
| POST /api/v1/auth/login | 登录，统一错误和限频 |
| GET /api/v1/auth/session | 验证当前会话并取得CSRF值 |
| POST /api/v1/auth/logout | 校验Origin/CSRF后撤销会话 |
| POST /api/v1/auth/activity | 明确用户交互续记空闲时间；自动轮询不能永久续命 |
| GET /api/v1/events | 来源/类型筛选、稳定游标分页和增量读取 |
| GET /api/v1/events/{event_id} | 事件详情、来源和原文版本关联 |
| GET /api/v1/sources | 已登录可查来源状态，不返回凭证 |
| GET /api/v1/status | 已登录可查版本、存储可用性和服务时间 |
| GET /health/live | nginx精确代理的JSON存活布尔，不公开版本、来源或机器详情 |

没有公网“随意创建事件”接口；合成测试记录由服务器本地管理命令创建，未来采集器复用同一写服务。没有平台配置 CRUD、设备回执、手机 WSS、下单或 AI 接口。

## 登录、隐私与刷新方式

- 推荐绝对会话12小时、无用户活动30分钟后到期；参数可配置，后台轮询不算用户操作。
- 登录失败按用户名和IP分别计数，推荐5次/15分钟；返回“尝试次数较多”，不泄露真实账号。密码用Argon2id，session随机且数据库只保留摘要。
- Cookie为Secure、HttpOnly、SameSite=Strict，写操作校验同源Origin和会话CSRF；CSRF由服务器密钥与Cookie会话确定性派生，刷新或多标签可重新取回同一值，JavaScript无法读取原会话令牌；所有敏感查询禁止浏览器缓存，退出或401清除敏感视图。
- 采集原文不可信，只显示文本，不执行HTML，不自动拉取原文中的远程图片/链接；外链仅允许http/https。
- 可见页面每5秒串行增量查询；超过一页的新增继续取完，不跳过中间事件。读旧信息时只提示“有新记录”，由你点击查看。页面隐藏暂停，恢复后补查。
- 5秒是刷新周期，不是保证5秒内完成所有平台检测；真实采集延迟要到对应平台阶段实测。Web不保证关闭、锁屏或后台后继续提醒或叫醒。
- 自建与TLS保护传输，不表示服务器看不到原文或已做端到端加密。备份、数据与运行密钥均有独立受限目录，不进入Git或普通日志。

## 怎么判定通过

| 验收方向 | 证据 |
|---|---|
| 认证 | 匿名401、凭证错误/限频、Origin/CSRF拒绝、Cookie标志、过期和注销后旧令牌无效 |
| 存储 | 重复重放、A→B→A、并发唯一、半写回滚、未知schema拒绝、重启和隔离恢复 |
| 浏览器 | 实际浏览器登录→真实API合成记录→详情/版本→状态→退出；不只做组件截图 |
| 错误恢复 | 断网/500保留旧结果并标记；401清屏；真正空列表不冒充请求失败 |
| 界面 | 360/768/1440px、200%缩放、长中文/URL、焦点和触摸；K50真实软键盘提交不遮挡 |
| 部署 | 非root、回环后端、可信TLS、API不误回SPA、续期模拟、优雅重启、备份与失败发布回退 |

自动测试由执行者完成，截图与日志脱敏归档。最后你在浏览器确认四页面和K50软键盘；缺真实手机证据的项目保持待验，不拿桌面模拟替代。阶段通过仍只证明基础Web可用，不表示平台监控已经完成。

## 部署和回滚边界

沿用现有证书与续期，新业务服务使用独立非root账号、回环18082、独立数据库；静态资源从当前发布目录提供。root保管0600环境文件，由systemd读取后注入；应用只写自己的受限数据目录，nginx只读Web静态文件，无法读取密钥或数据库。发布前重新读取服务器实际状态，不依据旧记录判断。发布按提交号目录并原子切换current，保留旧配置与一致性数据库备份。健康检查失败退回上一发布；恢复验证在独立目录，不覆盖正在使用的库。遇不兼容schema先停并确认迁移决策，不直接启动旧程序读取新库。
