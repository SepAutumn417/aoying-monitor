# 熬鹰资本多平台监控

## What This Is
先建设个人使用的自有服务端与Web界面，完成监控后再规划原生安卓App，跟踪熬鹰资本的观点、动态、开仓和仓位变化。境外服务器采集，Web展示原文、仓位和变化，用户自行决策操作；手机后台接收与叫醒延后到App里程碑。

## Core Value
稳定采集熬鹰资本真实观点与仓位变化，在Web及时清楚地展示并追溯来源，不把行情刷新误认为操作。

## Requirements
### Validated
尚无已交付的端到端产品能力；事件日志两项测试通过属于原型证据，不当作业务验收。
### Active
- [ ] 先完成安全服务端与Web时间线、仓位、变化、来源和状态展示。
- [ ] Telegram四话题监控，支持同一消息编辑产生的仓位操作。
- [ ] Web统一仓位、观点、动态、变化历史与来源。
- [ ] X/Fomo/OKX逐一核实权限后接入。
### Out of Scope
- 自动下单/平仓：本轮辅助人工跟随。
- Gotify或第三方通知SaaS：已结束试验并清除。
- 声称系统级推送或必达：当前不依赖厂商资格，后台能力须实测。

## Constraints
- 隐私：消息不经第三方通知SaaS，凭证不入Git；自建/TLS不等于端到端加密，服务器仍能读原文。
- 手机后台：真实匹配Android14服务用途，不借错误类型绕过限制；强停/关机/断网边界明确。
- 来源：新Telegram授权会话；X/Fomo/OKX入口待提供，不假设私有订单可读。
- 流程：用户选阶段方案确认后执行，标准粒度、规划入Git、研究/审查/验证开启，允许子代理；阶段执行依次推进。
- 发布：已授权独立新项目push与服务器实测，不扩展为自动交易或外部AI披露。
